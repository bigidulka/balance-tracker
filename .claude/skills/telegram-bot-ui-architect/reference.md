# Reference: Telegram UI Rules (aiogram)

## 1) UI architecture
- Один пользователь = один поток = одно главное сообщение.
- Навигация только inline-кнопками.
- Переходы экранов только через edit текущего сообщения.
- Без новых бот-сообщений при навигации.

## 2) Route-aware Back
- Back должен вести в фактический предыдущий экран.
- Запрещен static back target для multi-parent экранов.
- Хранить navigation stack + source route/entry context.

## 3) Input flow (FSM)
1. Нажатие inline-кнопки действия.
2. FSM в режим ожидания.
3. Edit главного сообщения в режим ввода.
4. Пользователь отправляет сообщение.
5. Сообщение пользователя удаляется.
6. Edit главного сообщения с результатом.

## 4) Formatting policy
- Использовать `aiogram.utils.formatting`.
- Предпочтительно: `Text`, `Bold`, `as_section`, `as_key_value`, helpers для списков.
- Акценты и предупреждения: `BlockQuote` (или entity-safe fallback по версии aiogram).

## 5) Data access policy
- Все данные (db/session/repos/user/profile/roles/settings) приходят через middleware.
- В handlers запрещены прямые DB запросы и ручная загрузка user/context.
- Handlers = orchestration only.

## 6) Error recovery
- stale/invalid callback: мягкая перерисовка актуального экрана edit-ом.
- state/navigation desync: возврат в ближайший безопасный экран раздела edit-ом.
